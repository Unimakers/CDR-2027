# 2026-11-20 : LiDAR LD06 et tirette

## Électronique

Branchement du LiDAR **LD06** et de la **tirette** sur la carte head (sur NP3). Pas besoin des moteurs ni du 24 V pour ce test.

| Élément | Connecteur | Broche |
|---|---|---|
| **LiDAR LD06** | J5 (head) | Données sur GPIO43 |
| **Tirette** | J6 (head) | GPIO12 |

## Code

Écriture du **test 8** ([`test8_lidar.cpp`](https://github.com/Unimakers/CDR-2027/blob/main/project/firmware/RB_esp32/breadboard/test8_lidar.cpp)), copié dans `main.cpp` pour être flashé.

Déroulement :

1. Au démarrage, si la tirette n'est pas en place, on attend qu'elle soit insérée.
2. Quand on **tire la tirette**, les scans du LiDAR sont envoyés au format [Teleplot](https://teleplot.fr/) pour les visualiser.
3. Quand on **remet la tirette**, l'envoi s'arrête ; on peut la retirer pour relancer.

La LED clignote vite pendant l'envoi et lentement en attente de la tirette.

### Points techniques

- **Anti-rebond** de 50 ms sur la lecture de la tirette.
- **Buffer de réception agrandi** (4096 octets au lieu de 256) : afficher un scan sur l'USB prend plusieurs millisecondes, et le buffer par défaut débordait (erreurs CRC, paquets perdus).
- **Détection automatique de TX/RX inversés** : le code écoute 1 s sur GPIO43, puis sur GPIO44 si rien n'arrive.
- **Diagnostic toutes les secondes** : octets reçus, scans par seconde, nombre de points, vitesse de rotation, erreurs CRC.

| Diagnostic | Signification |
|---|---|
| ~0 octet/s | Rien sur GPIO43 : vérifier le câblage de J5, l'alimentation du LD06, TX/RX |
| ~2100 octets/s mais 0 scan/s | Données reçues mais pas décodées (erreurs CRC ?) |
| ~10 scans/s, ~450 points | LiDAR OK |
